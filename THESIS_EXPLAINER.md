# Davao Curated Food Finder: Thesis Explainer

This explainer is based only on the files in this project. A code citation names the file and function; a saved-result citation names the artifact and the relevant JSON/CSV section. “NOT FOUND” means the requested fact is not evidenced in the inspected code or saved artifacts.

## 1. END-TO-END FLOW (origin to final output)

### A. What runs from the browser

`Main.html` does not expose a DEEPSEEK or GPT-4O-MINI selector. Its submit handler posts the query, conversation history, and previously shown names to `api.php`; its result renderer displays local records and online finds separately. The grid configurations are evaluation overrides, not choices a normal visitor makes in the page. ([Main.html](./davao_food_finder/Main.html) — submit handler and `renderPlaces()`; [api.php](./davao_food_finder/api.php) — evaluation override validation; [run_evaluation.php](./davao_food_finder/evaluation/run_evaluation.php) — `sendSingleApiRequestOnce()`.)

```text
Browser: submit handler
  -> POST api.php {query, history, shownNames}
  -> PHP request validation and dataset load
  -> parse intent / scope
  -> provider pipeline
  -> critique/refinement when enabled
  -> ID, URL, scope, and duplicate checks
  -> final JSON {answer, results, webResults, metrics, ...}
  -> Main.html renders local and online cards
```

The browser limits query length to 300 characters and aborts a request after 180 seconds. The API validates the POST body, requires a query, caps history at 12 and shown names at 50, then loads cached or source records. Intent parsing and search setup happen before provider dispatch. The HTTP response is decoded by the browser and rendered as cards. ([Main.html](./davao_food_finder/Main.html) — submit handler and `renderPlaces()`; [api.php](./davao_food_finder/api.php) — top-level POST handler, `parseQueryIntent()`, response construction.)

### B. DEEPSEEK and GPT-4O-MINI grid configurations

The grid is built by `run_evaluation.php` and passed to `api.php` using an evaluation block. The saved 2026-11-07 test artifact contains 22 configurations: 11 DEEPSEEK and 11 GPT-4O-MINI variants. For each provider, the grid uses temperatures 0.0, 0.1, 0.3, 0.5, and 0.7 with `baseline` and `strict_grounding` prompts, plus temperature 0.9 with `strict_grounding`. The saved artifact records three trials, seed 42, test split, and default cache. ([run_evaluation.php](./davao_food_finder/evaluation/run_evaluation.php) — `parseArguments()`, configuration construction, `sendSingleApiRequestOnce()`; [eval_20261107_082850.json](./davao_food_finder/evaluation/results/eval_20261107_082850.json) — `reproducibility_manifest` and `summary`; [eval_20261107_082850_summary.csv](./davao_food_finder/evaluation/results/eval_20261107_082850_summary.csv) — configuration rows.)

Common API processing validates the request, loads places, calls `parseQueryIntent()`, may gather web evidence, then dispatches by provider. For the DEEPSEEK grid, `answerWithDeepSeek()` uses the hosted DeepSeek API when configured and otherwise uses its local/Ollama path. For GPT-4O-MINI, `answerWithGPT4oMini()` makes the standalone model call. These are not the five-stage hybrid path. In the saved grid all provider configs use the agentic loop, so the ranking response can then pass through `runAutonomousRefinementLoop()`. ([api.php](./davao_food_finder/api.php) — `parseQueryIntent()` call and provider dispatch; [web_reasoner.php](./davao_food_finder/src/web_reasoner.php) — `answerWithDeepSeek()`, `answerWithGPT4oMini()`, `runAutonomousRefinementLoop()`; [run_evaluation.php](./davao_food_finder/evaluation/run_evaluation.php) — grid configuration construction.)

```text
Evaluation grid -> api.php -> parseQueryIntent()
  -> optional Playwright evidence collection
  -> DEEPSEEK: answerWithDeepSeek()
     OR GPT-4O-MINI: answerWithGPT4oMini()
  -> autonomous critique/refinement when agentic=true
  -> validate IDs / sanitize web results / deduplicate
  -> final JSON -> evaluator records metrics
```

### C. HYBRID five-stage pipeline

For the default hybrid provider, Stage 1 plans a Davao-focused search query with GPT-4O-MINI. Stage 2 collects Playwright evidence. Stage 3 asks GPT-4O-MINI to structure that evidence as JSON. Stage 4 asks DeepSeek R1 to reason over the structured evidence, local records, and conversation. Stage 5 asks GPT-4O-MINI to produce the final answer and candidate IDs. ([api.php](./davao_food_finder/api.php) — `planSearchQueryWithGPT4oMini()`, `collectPlaywrightEvidence()`, provider dispatch; [web_reasoner.php](./davao_food_finder/src/web_reasoner.php) — `planSearchQueryWithGPT4oMini()`, `answerWithHybridPipeline()`.)

```text
Main.html submit
  -> api.php: loadDavaoPlaces() -> parseQueryIntent()
  -> Stage 1 planSearchQueryWithGPT4oMini()
  -> Stage 2 collectPlaywrightEvidence()
  -> Stage 3 GPT-4O-MINI evidence structuring
  -> Stage 4 DeepSeek R1 reasoning
  -> Stage 5 GPT-4O-MINI final response
  -> runAutonomousRefinementLoop() if enabled
  -> output checks and deduplication
  -> final JSON -> Main.html cards
```

If the OpenAI key is unavailable, the pipeline skips the OpenAI stages and tries the DeepSeek/evidence fallback. A Stage 1 error avoids further OpenAI calls; Stage 3 or Stage 5 failure can use evidence/local fallback; Stage 4 failure can still permit Stage 5 with the structurer output. The response includes status telemetry for stages; the page considers the hybrid flow successful only if stages 1, 3, 4, and 5 are marked `ok`. ([web_reasoner.php](./davao_food_finder/src/web_reasoner.php) — `answerWithHybridPipeline()`, `answerWithDeepSeekPipelineFallback()`, `answerWithEvidenceFallback()`; [Main.html](./davao_food_finder/Main.html) — hybrid status indicator.)

The browser-facing page shows “Online finds” and “Local finds”; those labels indicate evidence origin, not model provider. A normal web request defaults to hybrid. Evaluation providers are accepted only from loopback requests. ([Main.html](./davao_food_finder/Main.html) — `renderPlaces()`; [api.php](./davao_food_finder/api.php) — provider default and loopback evaluation override guard.)

## 2. DATA ORIGIN AND PREPARATION

### Local dataset

The active data files are `data/ph_restos_2025.csv` and `data/ph_reviews_2025.csv`. `loadDavaoPlaces()` reads CSV or spreadsheet rows, and `api.php` caches the normalized place index in `data/.places-cache.json`, rebuilding it when its file signature or schema version no longer matches. The restaurant cache signature uses file name, size, and modification time. ([search.php](./davao_food_finder/src/search.php) — `csvRows()`, `worksheetRows()`, `loadDavaoPlaces()`; [api.php](./davao_food_finder/api.php) — dataset cache load and signature.)

The loader uses restaurant fields including name, address, city, food type, price range, description, rating, review count, StoreId, and source. It enriches records with branch/address details, review snippets and thematic signals, and observed price evidence. The Davao filter accepts records identified as Davao City; non-Davao records are excluded from this local candidate corpus. IDs are derived from normalized name, address, and city, while duplicates merge missing fields and signals. ([search.php](./davao_food_finder/src/search.php) — `loadDavaoPlaces()`, `isDavaoCity()`, duplicate/ID construction.)

Review rows are aggregated by StoreId. The loader accumulates review counts, positive-sentiment scores, thematic signals, up to 40 extracted peso mentions, and up to three snippets. A rating must be numeric and greater than zero; if the restaurant rating is missing or zero, available positive review scores may fill it. A missing/zero reviewer count is filled from review-row count if available. Otherwise a missing rating remains null, not a zero-star rating. The UI displays “No rating yet” for missing/invalid ratings. ([search.php](./davao_food_finder/src/search.php) — `loadDavaoPlaces()`; [Main.html](./davao_food_finder/Main.html) — `ratingMarkup()`.)

The README identifies the source as Kaggle’s “Philippine Cities Food Panda Resto Reviews,” author BwandoWando, CC BY-NC-SA 4.0; it states content updated 2025-04-18 and Kaggle page modified 2025-04-19. URL: https://www.kaggle.com/datasets/bwandowando/food-panda-restaurant-reviews. Download date is NOT FOUND. The data README names `ph_restos_2025(1).csv`, but the checked-in file and project README name `ph_restos_2025.csv`; this filename discrepancy is present in the repository. ([data/README.txt](./davao_food_finder/data/README.txt) — source statement; [README.md](./davao_food_finder/README.md) — dataset names; `loadDavaoPlaces()` in [search.php](./davao_food_finder/src/search.php) — actual filenames.)

### Live web evidence

The collector tries Brave, DuckDuckGo, Bing, and Photon/OpenStreetMap; if it still has fewer than three candidates, browser-based Bing and DuckDuckGo searches are used. It deduplicates URLs and returns a limited number of fetched evidence items. Photon place lookups are limited to named food venues in Davao City, Philippines. ([web-search.js](./davao_food_finder/scripts/web-search.js) — `run()`, `fetchPhotonPlaces()`.)

The Playwright collector normalizes the query to Davao/food, runs the web-search child process, and stores non-empty evidence. It rejects selected non-food/low-value pages, some aggregators/listicles when configured, and browser content with bot, CAPTCHA, or access-denied markers. Search snippets and pages are candidate evidence; later prompts and URL checks still determine whether the system may present them. ([web-search.js](./davao_food_finder/scripts/web-search.js) — `isLowValueNonFoodUrl()`, `run()`; [web_reasoner.php](./davao_food_finder/src/web_reasoner.php) — `collectPlaywrightEvidence()`, `rejectListicleAndAggregatorEvidence()`, `sanitizeWebPlaces()`.)

The web cache key is SHA-256 over a version tag, normalized/lowercased query, and price-lookup queries. Default TTL is 43,200 seconds (12 hours). `cold` and `bypass` skip cache reads; `warm` may serve an expired entry and does not scrape on a miss; `none`/`disabled` bypass collection. Thus a default-policy evaluation can use cached rather than newly scraped evidence. ([web_reasoner.php](./davao_food_finder/src/web_reasoner.php) — `collectPlaywrightEvidence()`.)

## 5. METRICS

The formulas below describe the evaluator, not an independent human judgment. Per-case examples must be read from saved detailed runs; if the artifact does not contain a per-case value, that example is marked NOT FOUND rather than inferred from a configuration average. ([metrics.php](./davao_food_finder/evaluation/metrics.php) — metric functions; [run_evaluation.php](./davao_food_finder/evaluation/run_evaluation.php) — case aggregation and saved `detailed_runs`.)

| Metric | Implemented formula / inputs | Worked example from a saved case |
|---|---|---|
| P@5 | Relevant unique normalized names in first five / 5; relevance means grade ≥1. Input: returned ranking and ground-truth grade map. | BASELINE-LOCAL Q004: 4 hits / 5 = **0.8**. |
| R@5 | Relevant unique hits in first five / count of positive-grade ground-truth items. | BASELINE-LOCAL Q004: 4 / 30 = **0.1333**. |
| R@10 | Relevant unique hits in first ten / count of positive-grade ground-truth items. | BASELINE-LOCAL Q004: 8 / 30 = **0.2667**. |
| NDCG@5 | Sum of `(2^grade − 1) / log2(rank + 1)` in first five, divided by ideal DCG from sorted available grades; capped at 1. | BASELINE-LOCAL Q004: **0.7465**. |
| MRR | Reciprocal rank of the first relevant unique result; zero if none. The scorer scans up to rank 20. | BASELINE-LOCAL Q004: first relevant at rank 1, so **1/1 = 1**. |
| Constraint item pass | For returned top-five items, number passing all applicable constraint dimensions / items checked. | BASELINE-LOCAL Q004: item pass rate **1.0**. |
| Constraint strict pass | Binary: all checked venues are in Davao, no exclusion or forbidden-name violation, and item pass rate ≥0.6. | BASELINE-LOCAL Q004: `strict_pass=true` (**1**). |
| Scope accuracy | Mean per-case/trial scope outcome. In-scope passes if not falsely rejected and Davao-only check passes; out-of-scope passes only when rejected with no local or web recommendations. | Latest regression S003: `scope_passed=true` (**1/1**). |
| Follow-up resolution | A multi-turn case passes when it is not falsely marked out of scope, P@5 >0, and strict constraints pass; scope-refusal follow-ups use the refusal check. | DEEPSEEK-T0.0-BASE MT007: `followup_passed=true`, P@5 **0.8**, strict pass true (**1**). |
| Faithfulness | Evidence-support rate: passed evidence-support checks / evidence checks; validator defaults to 1.0 when there are no checks. | DEEPSEEK-T0.0-BASE D001: `evidence_support_rate=1.0`. |
| Factual correctness | Passed fact checks / fact checks; validator defaults to 1.0 when there are no checks. | DEEPSEEK-T0.0-BASE D001: `factual_correctness_rate=1.0`. |
| Web source support | Supported web items / web items checked; null if there are no web items. | DEEPSEEK-T0.0-BASE D001: `web_source_support_rate=1.0`; its missing-source/error counts are zero. |

## 8. STATISTICS

Bootstrap intervals resample the case-level values with replacement 2,000 times using a deterministic xorshift32 generator and a seed; the 2.5th and 97.5th percentiles form the interval. For n=1, the interval collapses to the observed value. This interval describes the sampled cases under this benchmark; it does not address representativeness of the cases. ([statistics.php](./davao_food_finder/evaluation/statistics.php) — `confidenceInterval95()`, `nextDeterministicRand()`, `percentileVal()`.)

The Friedman test ranks system scores within each case, averages tied ranks, applies a tie correction, and uses a chi-square approximation for its p-value. The paired Wilcoxon test compares per-case paired differences; it uses exact sign permutations for at most 14 nonzero pairs and a tie-corrected normal approximation for 15 or more. Holm-Bonferroni adjusts the pairwise p-values within the tested family. ([statistics.php](./davao_food_finder/evaluation/statistics.php) — `friedmanTest()`, `wilcoxonSignedRankTest()`, `pairwiseWilcoxonPostHoc()`.)

The unit of analysis is the case/scenario after trials are aggregated per case, not each repeated request as an independent observation. For 4 volatility conditions, there are 6 pairwise comparisons; a 22-configuration all-pairs family would contain 231 comparisons. A significant Friedman result says at least one condition differs, not which pair; a pairwise significant result indicates a difference on these paired cases, not causal superiority in live use. A nonsignificant p-value does not prove equivalence. ([run_evaluation.php](./davao_food_finder/evaluation/run_evaluation.php) — per-case aggregation and pairwise tests; [statistics.php](./davao_food_finder/evaluation/statistics.php) — `pairwiseWilcoxonPostHoc()`.)

The stored signed effect size is `z / sqrt(n_pairs)`; its sign depends on the A-minus-B ordering. For volatility, Friedman Q=18.8571, df=3, p=0.00029264; the 6-pair Holm family has significant static-vs-agentic p=.0117188, stale-vs-agentic p=.0195313, and no-loop-vs-agentic p=.0195313. The other three volatility pairs are nonsignificant (Holm p=1). This tests binary scenario pass, not separate precision/suppression metrics. ([statistics.php](./davao_food_finder/evaluation/statistics.php) — `friedmanTest()`, `wilcoxonSignedRankTest()`, `pairwiseWilcoxonPostHoc()`; [latest_volatility.json](./davao_food_finder/evaluation/results/latest_volatility.json) — `statistical_tests`.)

For the saved local three-system test run, Friedman tests were significant for NDCG@5 (p=.0008765), P@5 (p=.00001410), MRR (p=.00000827), and constraint (p=.0000000583), with n=38 paired cases. Its pairwise Holm family has 3 comparisons per metric: baseline differs from both no-loop and agentic for NDCG, P@5, and constraint, while no-loop vs agentic is nonsignificant (Holm p=.0625, .125, and .15625 respectively). MRR pairwise post-hoc results are NOT FOUND. ([eval_20261030_213623.json](./davao_food_finder/evaluation/results/eval_20261030_213623.json) — `statistical_tests`; [statistics.php](./davao_food_finder/evaluation/statistics.php) — pairwise test functions.)

A McNemar test is NOT FOUND in the evaluation code. ([statistics.php](./davao_food_finder/evaluation/statistics.php) — implemented tests.)
